# Scout 的证据驱动评估层

## 定位

Scout 保留五阶段工具链，但不把“运行了多少工具”作为核心产出。新增评估层回答三个问题：

1. 当前有哪些资产和观察，它们之间有什么可证明的关联？
2. 哪些资产值得优先审阅，理由和证据在哪里？
3. 与前一次报告相比，什么新增、持续存在、变化或本次未观察到？

本层只消费已有观察，不发起网络访问、不调用模型，也不自行选择攻击动作。

## 数据流

```text
工具输出
  → StageResult（保留阶段观察）
  → PipelineContext.merge（融合重复记录）
  → to_final_report（兼容原报告 + intelligence）
  → write_report（最终快照 + 可选 baseline 对比）
  → JSON / JSONL / Markdown

旧 JSON / JSONL
  → load_report（类型校验）
  → 同一个本地评估与导出流程
```

`--demo` 和 `--report` 在导入扫描 Agent、读取 Config 之前返回，因此无需第三方 Python 包、外部工具或 API 密钥。演示数据明确标为合成数据。

## 关联与证据

图中的节点类型包括域名、IP、服务、URL 和发现。边只表达直接观察：

- `observed_resolves_to`：输入情报报告了域名与 IP 的对应关系，不代表当前 DNS 验证。
- `exposes`：地址上观察到端口。
- `has_endpoint`：某主机出现了 URL。
- `has_finding`：发现位置属于该资产。

图不会推断“同 IP 所有站点均受某漏洞影响”。凭据线索也不会在缺少归属信息时强行关联到目标资产。

证据使用 JSON Pointer，例如 `#/stages/4/vulnerabilities/0`。优先定位原阶段数据；旧报告缺少阶段记录时定位顶层观察。聚合数据融合不会改写历史 `StageResult`。

## 风险模型

优先级规则固定且可复现：

| 信号 | 基础分 |
|------|--------|
| 模板匹配 critical / high / medium / low / info | 90 / 75 / 50 / 25 / 5 |
| 凭据检测线索 | 60 |
| HTTP 200 的配置、备份等敏感路径线索 | 30 |
| 需审阅的服务端口暴露 | 25 |

资产分数 = 最高信号分 + 不同类型信号的佐证加分。每多一种类型加 5，最多加 10，总分最多 100。相同类型的大量低危结果不能累加成高危。

这些分数只表示人工审阅优先级，不是 CVSS、业务风险定论或漏洞可利用性证明。路径 HTTP 200 可能是 soft-404；端口开放不证明未授权访问；密钥检测不证明凭据有效。状态将这些线索与工具匹配明确区分。

技术栈只用于画像和 AI 观察，不通过版本号直接推断 CVE。

## 稳定身份与复测

发现 ID 来自类型和规范化观察键的 SHA-256 摘要，不依赖时间戳、结果顺序或严重级别。模板匹配使用模板 ID（缺失时回退到名称）、匹配位置和协议类型。

URL 身份会规范化主机大小写、IDNA、默认端口和根路径，去掉 fragment；保留路径、查询参数顺序和非默认端口，避免合并实际不同的输入点。

对比前重建两份报告的评估层，忽略缓存的 `intelligence`：

- `new`：本次出现。
- `persistent`：两次均出现。
- `not_observed`：本次没观察到，不能据此关闭问题。
- `changed`：相同身份的严重级别、优先级、端口、技术栈或关联信息变化。

对比严格要求目标相同，但不能证明两次授权范围和工具覆盖相同。操作者必须检查覆盖信息后再判断是否修复。

## 兼容性与输出

保留原报告的顶层资产数组、`stages`、`summary`、`agent_decisions`、`ai_analysis`，新增 `schema_version: "2.0"` 和 `intelligence`。使用 baseline 时新增 `comparison`。

命令行只在分析完成后导出一次，JSONL 保存最终完整快照。直接调用 `ScoutAgent.run`、`run_with_ai`、`run_agentic` 仍默认保存，传入 `persist=False` 可交给调用方保存。`Pipeline.execute` 同样保留默认保存行为。

`--no-ai` 在阶段构造前清空当前 Config 实例的 AI key。Config 不再使用全局单例，避免一次禁用 AI 影响另一个调用。

结构化模型不导出捕获的 secret match、提取内容或响应片段。但输入报告的 raw_data、URL、路径、工具错误和 AI 文字仍可能敏感，不应将整个报告视为脱敏材料。

## 验证与已知限制

回归测试在本地使用合成数据和 mock，CI 覆盖 Python 3.10 / 3.13 与 Linux / Windows，不启动 HTTP 服务，不执行真实目标扫描。

已知限制：

- 现有工具封装有时仅记录日志而未返回错误，阶段 `recorded` 不等于工具成功；报告明确说明缺少工具级覆盖证明。
- 图是观察关系图，不是已验证的攻击路径或可利用链。
- 未提供资产业务重要性输入，优先级无法替代组织自身的风险评级。
- 真实工具版本、网络行为和扫描准确度需在单独授权的测试环境中做集成验证。
